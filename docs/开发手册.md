# DeskMate v1.0

常驻 Windows 桌面的整理工具：**Dock 快速启动**、**启动台**、**文件夹引用管理**、**全局搜索**、**托盘与设置**。

面向「桌面堆满文件夹、常用软件散落各处」的 Windows 用户。平台：Windows 10 / 11 x64。

> 最高约束：DeskMate 只保存文件夹**路径引用**。所有数据只写 `%APPDATA%\DeskMate\`，唯一例外是开机自启写 `HKCU\...\Run`。
>
> 除一处之外，任何功能都不碰用户文件：浏览某个文件夹时，那一行的右键菜单可以**重命名**（只改名字、不挪位置）和**移到回收站**（走 shell，可从回收站还原，且必须二次确认、默认按钮是「否」）。
> 这是用户 2026-10-17 明确点名要加的能力，口径当场定死：删除一律进回收站，绝不 `File.Delete`；改名绝不覆盖同名项。
> 卡片、收藏、桌面分类、搜索、启动台、Dock 全部仍然只读 —— 分类是虚拟的，文件位置永远不变。

### 界面自检（看不到 UI 时很有用）

```bash
src\DeskMate.App\bin\Debug\net8.0-windows10.0.22621.0\DeskMate.exe --smoke-test
```

逐个创建并显示 5 个窗口，把结果写进日志后自动退出。XAML 资源缺失、模板绑定错误这类只有真正渲染才会暴露的问题，都靠它兜住。
日志位置：`%APPDATA%\DeskMate\logs\deskmate-<日期>.log`。

条目模板（Dock 图标、文件夹卡片）只有在**有数据**时才会实例化，空配置自检测不到它们。
想连模板一起验证，先写一份带条目的 `config.json` 再跑自检：

```bash
# 注意：JSON 里的 Windows 路径用正斜杠即可（C:/Windows/...），可避免反斜杠转义踩坑
notepad %APPDATA%\DeskMate\config.json
src\DeskMate.App\bin\Debug\net8.0-windows10.0.22621.0\DeskMate.exe --smoke-test
```

这份自检也顺带验证了两条安全行为：坏 JSON 会被备份成 `config.json.corrupt-<时间戳>` 后回落默认值（不覆盖、不丢用户配置），
以及不存在的文件夹会被标记失效而不是崩溃。

自检现在还管这几件只有真渲染才暴露的事：

- **每个右键菜单的每一条叶子项都真打开一次并解析 `Command`**（Dock 图标、启动台磁贴、文件夹卡片、分组 Tab、搜索结果、托盘菜单）。绑定路径写错既不编译失败也不抛异常，只会点了没反应，所以这属于**硬失败**：任何一条解析不到，`--smoke-test` 就以非零码退出。
- **三个快捷键入口的动作**（搜索 / 启动台 / 文件夹面板）：注册成功不等于按下去会开出窗口，所以直接调它绑定的动作并断言窗口真的可见。
- **启动台网格真滚得动**：往磁贴上冒泡一个真的滚轮事件，断言滚动偏移跟着变（「全部」与「已隐藏」两页各验一次）。条目超过一屏却滚不动 = 下面那几行永远点不到，而「已隐藏」页是恢复误隐藏的唯一入口。
- **收藏与新建走一遍真的**：点卡片星星 → 断言状态翻转、切到「★ 收藏」页能看到刚收藏的那一条 → 再点回去（配置保持自检之前的样子）；然后验新建浮层，**判的是渲染出来的可见性**（没点「＋」时必须不可见、点了必须出现、取消后必须收掉），再验非法名拦住且按钮置灰、合法名放行。自检**不会真按「新建」** —— 那会在你自己的目录里落下东西，建文件本身由单元测试在临时目录里验。
- **预览栏展开时卡片区真的让了位**：量预览开合前后卡片宿主的宽度，没变窄就判失败（它退回成盖在上面的浮层是静默的，右边那一列卡片会看不见也点不到）。
- **星星在三种条目上都点得动**：预览行末尾、桌面文件卡片右下角、收藏页卡片 —— 找的是**渲染出来的那颗按钮**，然后执行它自己绑好的命令（不是绕过去调视图模型），再断言状态翻转、星星换成实心。命令解析成 `null` 是静默的：按钮照样画出来，点下去什么也没有。自检加进去的收藏最后逐条撤掉，用户自己收藏的一条都不能少。
- **收藏页单击只弹预览**：往收藏列表那一层抛一个真实的 `MouseLeftButtonUp`（`OriginalSource` 填卡片外壳，和真鼠标点进来一样），断言预览栏出现且有宽度 —— 单击直接打开外部程序就是用户报的那条。注意：**从卡片外壳自己 `RaiseEvent` 冒不出去**（祖先层挂了 `handledEventsToo` 的探针也不响），所以事件必须从列表层起手，这条写第一版时踩了一次。
- **面包屑每一段都真点得动**：从可视树里找出那些 `DataContext` 是 `BreadcrumbItem` 的按钮，段数要和视图模型一致、`Command` 不能是 null（命令经祖先取，写错就是静默点了没反应），然后真点「上一段」断言 `BrowsePath` 换了层，最后复位以免后面的步骤换了现场。再点一次已经选中的「全部」Tab 也必须退出浏览 —— 这条挂在命令上而不是属性变更通知上，因为 `SelectedTabId` 根本没变，通知不会响。
- **同层文件胶囊真能切文件**：内容页顶上那一行的胶囊是 `ItemsControl` 里的按钮，命令经祖先绑到视图模型 —— 写错就是静默 null、点了没反应。自检找出「当前那枚」和「另一枚」，执行后断言 `FilePreview` 真的换成了那个文件，并截图 `smoke-file-chips.png`（能同时看出高亮与横向滚动）。返回那条链由单元测试盯着：← 第一下必须回本层列表、回列表时列表实例不变（= 没重新枚举 = 滚动位置保住）。
- **按住空格「呼出 → 松手关闭」两头都验**：自检不许挪用户的鼠标，所以指针位置那条判不了；真正会坏的是**松手关不掉**（窗赖在屏幕上）。于是合成一次抬起分别发到放大窗和主窗，只要有一侧能收尾才算过 —— 只写一边（比如只监听主窗）就会在「系统把激活给了新窗」时失效，这条正是这么被抓出来的。
- **文件内容预览按格式各画一遍真的**：把所有受管文件夹扫一遍，**每一种格式各挑一个真实文件**（Office 还按 docx / xlsx / pptx 分开，走的是三条不同解析路径），逐个断言那块面板真画出了内容 —— 文本框里有字、压缩包列出了条目**而且右边大小那一列非空**、Markdown/Word 的块渲染出来了**且屏幕上不残留 `**` 星号**（星号露在外面就是用户说的「没渲染格式」）、PDF 的位图宽度 ≥ 显示宽度 × 系统缩放（只量高度会放过「渲一张小的再拉伸」，那正是字发糊的成因）。内容页还有一条反向断言：**没点任何文件时它一块都不许出现在可视树里**（它的 `Visibility` 绑到自己 DataContext 上就会一直盖住目录列表，绑定失败是静默的、`Visibility` 停在默认值 `Visible`）。每种格式各存一张 `smoke-file-content-<格式>.png`。
- **预览卡片的 × 热区独立**：真挂一批窗口到预览上，确认每张卡片的关闭热区非空、且不与「切窗口」热区重叠。
- **面板搜索真能搜到文件**：量一次搜索框宽度（低于 160 DIP 判失败），再打一个必然命中某张卡片的关键词，断言切到了搜索视图且有文件夹结果，并截图 `smoke-panel-search.png`（能同时看出桌面文件有没有混进来）。
- **右键菜单真打开并确认套上了主题样式**（圆角外壳），截图 `smoke-menu-*.png`：隐式样式失效是静默的，只有把菜单打开才看得见。
- **截图存证**：`%APPDATA%\DeskMate\logs\smoke-toast.png`（非模态提示出现的那一帧）、`smoke-search.png`（搜索结果列表）、`smoke-launcher-scroll-全部.png` / `smoke-launcher-scroll-已隐藏.png`（滚到底之后的启动台，能同时看出图标有没有取到）。状态断言只能证明「没抛异常」，截图才能证明它真的画在屏幕上、位置没跑偏。

## 4. 发布

```bash
dotnet publish src/DeskMate.App/DeskMate.App.csproj -p:PublishProfile=win-x64-singlefile
```

产物在 `artifacts/DeskMate/`：

- `DeskMate.exe`（约 150 MB，self-contained + ReadyToRun，目标机器**无需安装 .NET 运行时**；开 R2R 换来启动更快，代价是体积比不开多约 17 MB）
- 5 个 WPF 原生库：`wpfgfx_cor3.dll`、`PresentationNative_cor3.dll`、`PenImc_cor3.dll`、`D3DCompiler_47_cor3.dll`、`vcruntime140_cor3.dll`
- `DeskMate.pdb` 等符号文件（保留是为了全局异常日志能给出行号）

默认 pubxml 已开启 `PublishReadyToRun`（把三个程序集预编译成 R2R 镜像，省掉启动时的 JIT）。实测冷启动数据：

| 场景 | 耗时 |
| --- | --- |
| 进程启动 → Dock 与托盘就绪（热缓存） | 约 0.7 s |
| 发布后第一次冷跑（139 MB bundle 首次读盘） | 约 1.7 s |

两者都在「启动 < 2 秒」之内。测量方式：记录进程启动时刻，与日志里 `DeskMate 启动完成` 的时间戳相减。

这是 **WPF 的平台限制**，不是配置没写对：`PublishSingleFile` 无法把 WPF 的原生库塞进 bundle。两种可选形态（在 pubxml 里改一行即可）：

| 目标 | 做法 | 代价 |
| --- | --- | --- |
| 严格只有一个 exe | `<IncludeAllContentForSelfExtract>true</IncludeAllContentForSelfExtract>` | 首次启动把约 160 MB 原生库解压到 `%TEMP%`，第一次明显变慢 |
| 体积减半 | `<EnableCompressionInSingleFile>true</EnableCompressionInSingleFile>` | 启动时需在内存里解压托管程序集，多花 100~300 ms |

默认配置选择了**启动最快**的形态，优先满足「启动 < 2 秒」这条性能底线。

## 6. 关键设计决策

**Dock 悬停链路上有两个「静默失效」的坑，都已用注释钉住**（`Controls/DockItemControl.xaml.cs`、`DockWindow.ShiftNeighbors`）：① 用 `AddHandler` 挂在窗口上的处理器，`sender` 永远是窗口，而 `RoutedEventArgs.Source` 会被路由改写成外层 `ItemsControl` —— 所以悬停事件参数自己带 `Control` 字段；② 样式 Setter 里的 `Freezable`（比如 `TranslateTransform`）会被冻结并被所有容器共用一份，对它 `BeginAnimation` 直接抛「对象已冻结」—— 所以让位用的位移由代码逐个容器新建。这两个坑的表象都是「悬停没反应、预览不出来」，且不留可定位的痕迹，因此链路上每个分支都补了 Debug 日志。

**Dock 项与启动台磁贴都要先把路径「还原」再拿去比进程**。`.lnk` 里的目标可能写成环境变量（`%windir%\...`）或 8.3 短路径（真机上遇到过 `QODERC~1.EXE`），短路径当进程名永远对不上 —— 表现就是运行指示不亮、悬停没预览、点一下又开一个实例。`ProcessProbeService.ResolveExecutablePathAsync` 统一做环境变量展开 + `GetLongPathName` 还原，见 `Interop/PathInterop.cs`。

**图标与快捷方式必须走一条专用 STA 线程**（`Core/Services/StaScheduler.cs`）。`IShellLink` 是 COM 组件，而 `Imaging.CreateBitmapSourceFromHIcon` 会创建 `DispatcherObject`，两者在线程池线程上行为不稳定。所有图标先在这条线程上生成并 `Freeze()`，再交给 UI 线程消费，因此缓存命中时零跨线程开销。

**HICON 由 Interop 以 `IntPtr` 返回，转换放在 Core。** 这样 `DeskMate.Interop` 不需要任何 NuGet 依赖（`System.Drawing.Common` 整个包被省掉了）。

**启动台的虚拟化按「行」做。** `WrapPanel` 不参与 UI 虚拟化，几百个图标会一次性全部生成实体；所以 VM 先把磁贴切成行，外层用 `VirtualizingStackPanel`，只 realize 可见行。

**Dock 的悬停动画只改 `RenderTransform`**（ScaleTransform + 相邻容器的 TranslateTransform），不碰 Margin —— 后者会触发重排，撑不住 60 FPS。

**运行指示点用一次进程快照供整排图标**（`Process.GetProcesses()` 每 3 秒一次，且逐个 `Dispose`），比每个图标各自 `GetProcessesByName` 少一轮全表扫描，也不会漏放内核句柄。

**图标解析链是 `.ico` 文件 → PE 资源 → Shell 兜底。** 快捷方式自定义了图标位置时先分两种情况：位置指向一个独立 `.ico` 文件（Qoder、STM32CubeProgrammer 都是这种写法）就直接解码它，并且**按请求尺寸挑档** —— 一个 `.ico` 里通常塞着 16/24/32/48/64/256 好几张，而文件里的第一张往往是最小的，照第一张给就只有 16px，铺到 64px 的格子里糊成一团。其余情况先按请求尺寸走 `PrivateExtractIcons`（最清晰），取不到再问 `SHGetFileInfo` 要资源管理器实际显示的图标 —— UWP/商店应用、`.url` 快捷方式、目标本身是目录这三类只有后者能拿到。

`.ico` 这一路必须**先把字节读进内存、当场解码完再 `Freeze()`**，两个原因都踩过：用 `BitmapCreateOptions.DelayCreation` 返回的是「还没解码的帧」，它背后的 decoder 属于图标那条 STA 线程，UI 线程拿去用时补解码会直接抛「调用线程无法访问此对象」，格子整块空白；而让 decoder 自己去开文件路径，它会一直占着句柄，等于 DeskMate 锁住了别人的图标文件（单元测试里就是靠「用完能不能删掉这个 `.ico`」把这条钉住的）。
自定义图标位置一律**由 `.lnk` 现场解析**，不把 `ShellLink` 返回的图标位置字符串存进缓存：那串东西常写成 `%windir%\system32\shell32.dll,-50`，未展开的环境变量和 `,-N` 索引一旦丢了就注定取不到图标（启动台部分格子空白正是这个原因，已在 v1.0 修复）。

**换肤靠替换 App.xaml 里 0 号合并字典**，所有颜色走 `DynamicResource`，所以切主题不需要重建任何窗口。

## 7. Dock 入口、添加应用与噪声过滤

Dock 左端两个固定按钮 + 右端一个 ＋，空 Dock 也能直接操作：
| 位置 | 图标 | 作用 |
| --- | --- | --- |
| 最左 | 四方格 | 打开启动台 |
| 左二 | 文件夹 | 打开文件夹管理 |
| 最右 | ＋ | 打开启动台（在那里右键应用 → 「添加到 Dock」） |

### 运行区：开着窗口的应用自己冒出来

Dock 的一条其实是两段拼起来的：**运行区**（当前有主窗口的应用，临时、不落盘）+ **固定区**（`config.DockItems`）。顺序是 `[启动台][文件夹] → 运行区 → 分隔线 → 固定区 → [＋]`。

- **判定**：`Process.MainWindowHandle != 0` —— 用的就是 Shell 眼里的「这个进程的主窗口」，所以缩回托盘的微信/QQ 天然不进运行区（它们没有窗口可切，摆上去只会误导）。
- **去重**：按规范化后的 exe 路径（大小写不敏感）比对，已经固定的应用只在固定区出现一次，靠运行指示点表达「它在跑」。
- **排序**：按**进程启动时间升序**，先开的靠左。刻意不按「最近使用」排 —— 那样每点一下图标整条 Dock 就重排一次，鼠标追着图标跑，比 macOS 的写法更难用。读不到启动时间的受保护进程退到按名字排。
- **显示名**：文件版本信息里的 `FileDescription`（「微信」而不是进程名 `Weixin`），按路径缓存，不每轮读盘。
- **移除**：每 2 秒重算一次快照，应用一关图标就消失；固定项不受影响。
- **视觉分组**：两段之间一条 1px 分隔线（横着贴边是竖线、竖着贴边是横线），免得「图标自己冒出来」被当成故障。
- 运行区里的图标右键是「固定到 Dock」+「**关闭窗口**」，没有「从 Dock 移除」（它本来就不在配置里）。拖拽排序只作用于固定区，临时项不会因此被写进 `config.json`。
- **「关闭窗口」走 `WM_CLOSE`**（投消息给窗口，等价于用户自己点标题栏的 ×），不是杀进程：程序想弹「保存吗」照样弹，未保存的东西不会被 DeskMate 替用户丢掉。一个窗口都没有（缩回托盘那类）时会明确回一句「现在没有可关闭的窗口」，不会点了什么都不说。

往 Dock 上加东西的三种方式：

1. 启动台里右键某个应用 → **添加到 Dock**
2. 启动台里把磁贴**直接拖到底部 Dock** 上
3. 从资源管理器把 `.exe` / `.lnk` / `.url` **或文件夹**拖到 Dock 上（拖别的类型会提示，不会静默失败）

**文件夹可以直接钉在 Dock 上**（点一下就是资源管理器打开它）：常用目录不必每次先进面板。自动取的名字取不到时（比如盘根）直接用路径，不会留一个空名字。

Dock 图标右键：打开 / 打开文件位置 / **重新选择目标**（失效时用） / **重命名** / **更改图标** / **恢复自动图标** / 固定到最前 / 从 Dock 移除。

- **重命名**只改 Dock 上显示的名字，磁盘上的程序与快捷方式文件名不动；名字还是自动取的文件名时，「重新选择目标」会带着它一起换，用户自己改过的名字保留。
- **更改图标**挑一个 `.ico` / `.exe` / `.dll` 当图标来源（存进 `DockItem.IconOverride`），点下去启动的还是原来那个程序；「恢复自动图标」清掉它。
- 运行区（临时项）没有改名/移除，只有「固定到 Dock」—— 它本来就不在配置里。

### 自动隐藏时的触发热区

设置里勾了「自动隐藏 Dock」后，鼠标贴到屏幕边缘就把 Dock 唤出来。三个参数决定手感（都在 `DockWindow` 顶部）：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `HotZoneDip` | 14 | 边缘往内 14 DIP 都算热区。原来是 5px，光标必须正好压在那几行像素上，用起来就是「来回蹭几下才出」 |
| 热区形状 | 整条边 | 只判断「贴到那条边」，不再要求光标同时落在 Dock 的水平跨度内 —— Dock 只占中间一段，逼人在屏幕底部找位置 |
| `HotZoneInterval` | 50ms | 轮询光标位置的间隔，一次 `GetCursorPos` 很便宜 |

移出后延迟 800ms（`AutoHideDelay`）收起，滑入滑出动画 200ms。

### 全屏时让路（Dock 与任务栏遮罩一起）

全屏应用运行时 Dock 让路（核心原则），此时热区不响应；任务栏遮罩是同一条状态驱动的，一起收起来 —— 不然画面上就剩一块贴着壁纸的"色块"。

判据（`Interop/FullscreenDetector`）：前台窗口的矩形**覆盖**所在显示器（不是相等 —— 游戏跑非原生分辨率、DWM 不可见边框、DPI 取整都会差几像素，判相等就会漏，表现为 Dock 盖在游戏上），并排除四类：系统外壳窗口（桌面/任务栏/开始菜单）、被 DWM 遮罩的（别的虚拟桌面、挂起的 UWP）、我们自己的窗口、以及「最大化 + 带标题栏」的普通窗口（不然用户一最大化浏览器，Dock 就没了）。

**触发时机比判据更容易错**：光听 `EVENT_SYSTEM_FOREGROUND` 是不够的 —— **按 F11、点视频全屏、游戏切全屏都是同一个窗口就地改样式和矩形，前台窗口根本没换，那个事件一声不响**，表现就是"任务栏会藏，Dock 不会"。所以 `FullscreenService` 除了前台事件，还以 **400ms** 重算一次（一次判定就是几个 user32 调用），状态真变了才发事件。另外把判定拆成了 `Evaluate/Explain`，"铺满了但被某条排除挡下"会记一行 Debug 日志 —— 下次再报"全屏时还挡着"，日志一眼能看出是哪条判据挡的，不用猜。

### 文件夹面板的点击语义（资源管理器式两栏）

主区只有两种状态：**卡片网格**（挑文件夹）与**某个文件夹的内部列表**（挑文件）。进入内部后，右边那一栏是内容窗格，**列表和内容同时可见** —— 看了这个文件也还知道同层还有什么。

| 操作 | 结果 |
| --- | --- |
| 单击卡片 | 主区**走进这个文件夹**：卡片网格整块换成它的内部列表（名称 / 大小 / 修改时间 / ☆，目录在前、最多 50 项），**不**启动资源管理器 |
| 列表里单击目录 | 继续往里去一层（← 一层层退回来） |
| 列表里单击文件 | 右边内容窗格**就地看它的内容**（文本 / Markdown / 图片 / PDF / 压缩包条目 / Office 正文），左边列表不动，那一行高亮 |
| 收藏 / 分类 / 搜索里单击文件 | 只开右边内容窗格，**左边那一页原封不动** —— 点收藏里的 md 不该把收藏列表换成它所在的桌面 |
| 双击文件或目录 | 交给系统：文件按默认程序打开、目录在资源管理器里打开。**同时收掉内容窗格**（已经用源程序看真家伙了，那块临时预览没理由留着挡屏幕）。系统没给这类文件配关联程序时不会把你丢给「打开方式」面板 —— DeskMate 自己能看的，直接用自己的查看器放大打开，并说明为什么 |
| 顶部 ← / 内容窗格的 × | ← 的第一下**先收内容窗格**（回到只看列表），再按一下退上一层，退到入口就回到卡片网格 |
| 顶部路径（面包屑） | 从盘符到当前层，**每一段都能点**，点哪段直接跳到哪一层；跳完再按 ← 是继续往上退，不会被弹回刚才那个深角落 |
| 再点一次当前 Tab（如「全部」） | 立刻退出浏览回到卡片网格 —— 钻进去之后人的第一反应就是再按一下它，所以那一下必须是「回主界面」而不是空操作 |
| 内容窗格顶部那排胶囊 | 同层还有哪些文件一眼看到，点一下直接切过去 |
| Esc | 同上按顺序收；都收完了才关面板 |
| 换顶部 Tab / 开始搜索 | 自动退出浏览**并收掉内容窗格**，回到卡片网格（不然搜索结果会被列表挡住，看着像没反应） |

**预览是「随用随走」的**：内容窗格只属于「你正在看的那一页」。换类型 Tab（图片 → 压缩包）、换分组、走进另一个文件夹、点面包屑跳到别层、一开始搜索、或者双击把文件真的交给了源程序 —— 这些「离开原位」里的任何一种，窗格都自己收掉，不需要用户去点 ×。反过来，收起窗格也绝不换页：左边那一列永远还在你离开时的位置。

同一层里翻文件（◀ ▶、点胶囊）不算离开原位，窗格跟着换内容、列表不重枚举，所以滚动位置不会甩回顶部。

浏览全程只读列举 —— 不写、不移、不删任何东西。同一层里翻文件不会多压一个「返回」台阶；退回本层列表时不重新枚举，所以滚动位置不会被甩回顶部。

### 工具栏与分组：新建、改名、删除、撤销

工具栏：`添加文件夹` · `刷新` · `＋ 新建` · `更多`（扫描桌面文件夹 / 重命名当前分组 / 删除当前分组）· **搜索框** · `新建分组`。

不常用的三个动作收在「更多」里，是为了给搜索框让出位置 —— 七个按钮摊在一行会把搜索框压成几十像素，实测窄到根本点不中（这就是用户报的「搜索框太小」）。现在搜索框横向撑满剩余空间（`MinWidth=240`，本机实测 370 DIP），`--smoke-test` 会直接量它的宽度，低于 160 DIP 就判失败。

### 面板内搜索（跨文件夹与桌面文件）

在任何一页（收藏页除外）打字都进入搜索状态，结果**跨两类来源混在同一页**：受管文件夹（卡片原样，星星/新建都能用）+ 桌面上的文件（扩展名角标 + 大小 · 修改日期）。双击即打开。

- 为什么要有这一条：以前这里的关键词只在**当前 Tab 内**筛受管文件夹，于是「我记得桌面上有个课程表.pdf」在面板里永远搜不到，看起来像搜索坏了。
- 停在文档分类里也能搜到图片 —— 打字就是要找东西，不该先问「你现在停在哪个视图上」。
- **收藏页例外**：那一页打字是「在这几条里再筛一下」，不会把人甩到全局搜索结果。
- 匹配走 `PinyinMatcher.Score`（拼音首字母也行），桌面文件最多显示 60 条并在状态栏写明；一条都没搜到时给的话会指向 `Alt+Space` 的全局搜索（它会读受管目录的一层内容）。
- 清空关键词就回到原来那一页，Tab 的选择不变。

分组名校验规则集中在 `Core/Services/GroupNameRules.cs`，新建与改名共用同一套，边输入边提示：

- **空名字** → 「确认」置灰。刚弹出来就标红喊「不能为空」太吵，置灰已经表达清楚了。
- **长度** → 上限 20 字；输入框故意允许敲到 24 字，否则提示永远说不出口。
- **重名** → 「该分组名已存在，请换一个」。比对前先去首尾空格、且不区分大小写；内置的「全部 / 未分组」也算占用，否则会出现两个一模一样的 Tab。**改名时把自己排除在比对之外**，否则「名字没改直接点保存」会被自己的旧名判成重名。
- **提交** → 再去一次首尾空格后落盘。回车等于点「确认」，Esc 等于「取消」。
- **入口有两个**：工具栏按钮改「当前选中的分组」，Tab 上右键改「右键那一个」。以前只有「新建 + 删除」，名字打错一个字就得删了重建再把每个文件夹逐个换回去 —— 那是这套面板最难用的一处。
- **删除要先确认**，文案会写清「组内 N 个文件夹会退到未分组，文件夹本身不受影响」；删完的提示上带一个**「撤销」**按钮，点一下分组和成员关系都回来（只在本会话内有效，且只保最近一次）。
- 「全部」「未分组」和四个桌面分类标签都是内置视图：改名与删除都会挡下来并说明原因。
- Tab 一律带数量（`课程资料 3`），空组一眼就能看出来。

### 多选、批量与键盘

卡片支持 `Ctrl` 加选 / 去选、`Shift` 连选、`Ctrl+A` 全选当前视图；选中后右键菜单（换分组 / 颜色标签 / 移除）**一次作用在整批上**，状态栏会写「已选 N 张，右键可批量处理」。点卡片空白处或按 Esc 清掉选中 —— 不然批量状态悄悄留着，下一次右键就作用在没想到的卡片上。

键盘：`F2` 改选中卡片的显示名、`Delete` 移除选中引用（超过一张先确认）。焦点在搜索框里时这三个键仍然属于编辑操作，不会被抢走。

普通单击的语义没变：只开右侧预览栏，不开资源管理器。

### 两栏：主区走进文件夹，右边是内容窗格

窗口右边那一列（520 DIP）现在是**内容窗格**，只在选中文件时出现；主区（左边）在「卡片网格」与「某个文件夹的内部列表」之间切换。所以进入文件夹 + 看内容可以同时做，而不是像以前那样：列表和预览抢右边那一栏，看了内容就不知道同层还有什么。

两栏是**互不影响**的：内容窗格只由「点了一个文件」唤起，它从不换掉左边那一页。所以在「★ 收藏」「照片 / 文档 / 压缩包」这些桌面分类里、或者搜索结果里点一个 md / docx / pdf，左边照样是收藏列表 / 那个分类 / 搜索结果，只有右边的窗格画出这个文件的内容。左边只有三种情况会换页：点文件夹卡片（走进去）、点列表里的目录行、点顶部面包屑。

浏览列表按资源管理器的样子排：表头 `名称 / 大小 / 修改时间`，行尾一颗 ☆，目录在前、最多 50 项（截断会写在列表末尾那一行），顶部是 `← · 层名 · 完整路径 · ＋新建 · 在资源管理器打开`。选中哪一行，哪一行高亮 —— 右边那块内容对得上「它是列表里的哪一个」。

**行上右键**：`打开` / `在资源管理器中显示` / `重命名…` / `移到回收站…`。后两条是全应用唯一会动到磁盘的操作：改名只在这层里改（同目录已有同名、名字里有非法字符一律拒绝，什么都不改），删除走 shell 进**回收站**（还能还原），并且一定先弹二次确认、默认按钮是「否」。改完名或删完之后：列表立刻重数一遍、右边正看着它的内容窗格收掉、指向旧路径的那条收藏跟着改名或撤掉 —— 不会留下点开就报错的引用。

**卡片区是自适应几列的**：卡片宽度不再写死，由窗口报进来的实测宽度算出列数再平分（最小 196 DIP 一列）。所以右边内容窗格一开、或者滚动条出现导致可用宽度变化时，卡片会自己重排；本机实测整宽 1182 DIP 排 5 列，窗格展开后 646 DIP 排 3 列。以前写死 212/256 时，窗格一开左边刚好只塞得下一列，中间空一大片 —— 用户原话「文件本可以排成两排」。面板默认尺寸也从 1040×700 加到 1240×780。

`--smoke-test` 量的是这几件事：进入卡片后主区换成列表（宿主宽度实测 984 → 448 DIP）、卡片网格必须不可见、点文件后**列表与内容窗格同时可见且都有宽度**、选中行确实被标亮、`×` 只收窗格不收列表、`←` 最后能退回卡片网格；收藏那一步还专门点一次「收藏里的文件」，断言**左边仍然是收藏页**（`FavoriteCards` 还在、`PreviewItems` 是空的）—— 这条就是用户报「点收藏里的 md，左边变成了桌面内容」之后加的回归锁。以前那条「预览展开时卡片区要变窄」的断言已经不适用（浏览时网格整块让位），别照抄回去。

### 文件内容预览（自建查看器，不碰 COM）

在列表里点一个文件，右边的内容窗格就把这个文件本身画出来（左边的列表继续在那儿）。参考的是 QuickLook 的思路，但走的是它第二条路（自建查看器），**不挂系统 Shell 预览处理程序**：`IPreviewHandler` 是第三方 COM，会崩、会吞焦点、还得养一个「崩了就杀宿主」的机制。

| 类型 | 怎么画 | 上限 |
| --- | --- | --- |
| 文本 / 代码（`.c` `.h` `.md` 源码、`.uvprojx`、`Makefile`… ） | 等宽、**不换行**（代码换行会毁掉对齐），只读但可选可复制 | 读开头 512 KB，截断时切到最后一条完整行并写明 |
| Markdown | 按块渲染：标题分级、列表带序号、引用斜体、代码围栏有底色；块内的 `**粗**` / `` `码` `` 也渲染成真的粗体与等宽片段（Word 复用同一套行内渲染） | 前 800 块 |
| 图片（png/jpg/gif/bmp/ico/tif） | 等比缩放居中，灰底衬着 | 64 MB |
| PDF | **系统自带的 `Windows.Data.Pdf`** 逐页渲成位图。宽度按「显示 DIP × 系统缩放」算，正好 1:1 落在设备像素上；带 −/百分比/+ 缩放档，放大是**按更高像素重渲**而不是拉伸位图 | 128 MB / 前 2000 页 |
| 压缩包（zip/jar/apk/nupkg…） | 列条目 + 大小，**只列不解压** | 前 300 条 |
| OOXML（docx/xlsx/pptx 及带宏的） | 打开包读里面的 XML，**带结构**地抽：Word 的 `Heading N` 样式、或「整段加粗 + 字号 ≥13pt + 短行」→ 标题；加粗 run → 粗体片段；`w:tbl` → 一整块等宽表格（一行一个灰条会碎成斑马纹）。PPT 每页先给「第 N 页」，标题占位符单独成标题；Excel 是「工作表名 + 等宽行」 | 4000 块 |
| 其余（.doc/.rar/webp/二进制…） | 不装死：写清**为什么看不了**和下一步点哪 | — |

- **只读，而且是真只读**：所有读取一律 `FileShare.ReadWrite`，用户的 `.c` 正开在 Keil 里、日志正在被写、PDF 正被阅读器打开时都能预览，反过来也不会把这些文件锁住（`PdfPreviewSession` 因此是自己读字节再 `LoadFromStreamAsync`，不用 `LoadFromFileAsync` —— 后者会一直拿着句柄）。
- **编码不许猜错**：BOM → 严格 UTF-8 → GB18030 → Latin-1，并把实际用的编码名标在界面上；中文老工程按 UTF-8 解出来是乱码，那句说明就是给用户看为什么。
- **◀ ▶ 翻同目录的相邻文件**：顺序照目录列出来的样子，跳过隐藏/系统项与 `desktop.ini`；放大窗与窄栏共用同一个视图模型，一边翻页另一边跟着走。
- **内容页顶部的「同层文件」胶囊条**：把这一层还有哪些文件摊成一行可横向滚动的胶囊，当前那枚高亮并自动滚进视野，点一下直接切过去（不用先退回列表再找）。只有两个以上文件才出现，单文件目录里它是噪声。这解决的是「在很深的文件夹里点了一个文件，就看不到同层还有什么」。
- **返回不丢位置**：← 的第一下回到**本层的列表**（以前会跳过它直接上一层，深三层点一个文件一按 ← 就不知道自己在哪了）；回到本层时**不重新枚举**，列表实例原地保留，所以滚动条不会被甩回顶部；用 📁 回过本层之后栈里那条会消掉，← 不会白按一次。
- **⤢ 放大成独立窗口**：520 DIP 的窄栏读长文和 PDF 都太挤，放大窗 1080×760、Esc 关、单例（关掉是 `Hide()`）。
- **按住空格 = 放大，松手 = 收**（QuickLook 那套手感）。三个条件同时成立才拦这一下：正在看某个文件的内容、鼠标还在这个窗口上、焦点不在输入框或按钮上（空格在那两处是打字 / 激活按钮）。按住呼出时**不抢焦点**，并且主窗和放大窗**两边都备了松手收尾**（到底哪一侧收到那一下抬起，取决于系统把激活给了谁，只写一边就会出现「松手关不掉」）；被别的应用抢走前台时也会自动收，不会赖在屏幕上。已经用 ⤢ 手动开着放大窗时，空格不做按住呼出 —— 松手不该把别人手动开的窗关掉。
- 预览只是看：想真的打开仍然要双击，或者点内容页上的「用默认程序打开」。这两条走的是同一个出口 `OpenExternally`，里面处理了两种「点了但没打开」：
  - **系统没给这类文件配关联程序**（本机实测 `assoc .md` 查无此人，虽然 UserChoice 里有 Typora）：交给 shell 只会弹一个「你要用什么打开」的面板，用户读到的还是没打开。所以先问 `ShellAssociation.ExecutableFor`（走的是和 ShellExecute 一样的合并 UserChoice 那条解析链，落到 `OpenWith.exe` 一律算没关联）；DeskMate 自己能看的就直接用自己的查看器放大打开并说明原因，看不了的才把下一步讲清楚。
  - **接手的那个应用没到前台**：单实例应用（本机是 Typora）收到第二个实例转交的文件后，只更新自己那个已存在的窗口就完事，新进程立刻退出 —— 我们这边日志写着「已启动」，用户那边窗口还最小化着。所以启动后补一刀：等它的窗口出现，最小化的还原、不在前台的抬起来（**只抬起，绝不借任务栏那套 ToggleForeground**，那个语义会把刚打开的窗口最小化）。

### 收藏（★）

面板顶部第二个 Tab 是「★ 收藏 N」，跨分组汇总你标星的东西。

- **星星出现在你看到那个东西的地方**：文件夹卡片右下角、桌面分类 / 搜索结果里的文件卡片右下角、预览栏每一行末尾，都是同一颗 ☆（空心=没收藏，实心琥珀色=已收藏），点一下切换。放在条目上而不是工具栏，是因为「收藏哪个」的答案就是这一条，不用先选中再去别处找按钮。
- **收藏的只是路径**（`config.json` 的 `favorites`），不复制、不移动、不改名任何文件；取消收藏也只是去掉配置里的一行。
- **同一个路径在多处的星星会一起翻**：一个目录既是一张卡片、又是父目录预览里的一行，收藏它时两处状态同时更新，不会出现「这边收了那边还空心」。
- **收藏页与主视图同一套点法**：单击卡片只在右侧预览栏看内容（目录列它里面的东西，文件直接看它的内容），**双击**才用系统默认方式打开；右键菜单里「在预览栏看内容 / 打开 / 打开文件位置 / 从收藏移出」四条都在。
- 收藏页里目录、文件、压缩包一视同仁：目录显示条目数，文件显示「大小 · 修改日期」，角标是扩展名（ZIP / C / DOCX）。
- 面板里看不到的文件（不在桌面也不在受管目录），用工具栏上的「＋ 收藏文件或压缩包」，可多选。
- 路径不见了会写明「路径不存在」而不是静默消失，取消收藏的提示带「撤销」。

### 新建文件夹 / 文件

三个入口，差别只在「建在哪」，浮层里都会写明当前目标目录，还能点「换个位置…」临时改：

| 入口 | 建在哪 |
| --- | --- |
| 卡片右下角的「＋」 | 那张卡片对应的目录 |
| 工具栏的「＋ 新建」 | **桌面**（用户实际的桌面目录，被重定向到别处也跟着走） |
| 目录预览面板标题栏的「＋」 | 你正在看的那一层（下钻进子目录后也算） |

浮层里先选类型再写名字，一共七项：

| 类型 | 建出来 | 名字怎么算 |
| --- | --- | --- |
| 文件夹（默认） | 目录 | 照你写的建，名字里有点也算目录名（`v1.2` 是目录） |
| Word 文档 | `xxx.docx` | 自动补 `.docx`，你已经写了就不重复补 |
| Excel 工作簿 | `xxx.xlsx` | 同上 |
| PPT 演示文稿 | `xxx.pptx` | 同上 |
| Markdown | `xxx.md` | 同上 |
| 文本文件 | `xxx.txt` | 同上 |
| 其他（自己写后缀） | 看名字 | 不带后缀=文件夹，带后缀（如 `main.c`）=文件 |

- **Word / Excel / PPT 不是建个 0 字节空文件**：那种 `.docx` 双击会弹「文件已损坏，无法打开」。Office 自己的新建靠注册表里的 `ShellNew` 模板，而这台机器上 Office **根本没注册**（`Word.Document.12\ShellNew` 不存在），所以 DeskMate 自己按 OOXML 规范生成最小合法包（`Core/Services/OoxmlTemplates.cs`，docx / xlsx / pptx 三种），并已在本机装的 Word、Excel、PowerPoint 里真打开验证过（Word 读到文档、Excel 1 个工作表、PowerPoint 0 张幻灯片）。要加新类型就在这个文件里加一段，别改成写空文件。
- 边输边判：非法字符、以点或空格结尾、`CON`/`LPT1` 这类保留设备名、名字过长都会当场说原因，「新建」按钮同时置灰；输入框下面实时写出「将新建Word 文档：E:\Desktop\2026-2作业\报告.docx」。
- **只新建，绝不动已有的东西**：同名的一律拒绝（「这里已经有一个叫「x」的了」），不覆盖、不重命名、不删除；目标目录已经不在了也会挡住。
- 建完的提示带「打开」按钮，直接进那个新文件夹或打开那个新文件；从卡片入口建的还会刷新那张卡片的条目数。

### 右键菜单的外观

所有右键菜单（Dock 图标、启动台磁贴、文件夹卡片、分组 Tab、收藏卡片、搜索结果、托盘）共用 `Resources/Themes/Common.xaml` 里的一组**隐式样式**：圆角外壳 + 主题底色与描边 + 投影 + 30px 行高 + 悬停/子菜单展开高亮 + 主题色分隔线 + 禁用态半透明，跟随深浅色即时切换。以前是 WPF 默认那套白底直角 + 系统蓝高亮，压在深色面板上像别人家的窗口。

- 图标列与快捷键列用 `Grid.IsSharedSizeScope` + `SharedSizeGroup` 对齐；一条菜单里没有任何图标时整列宽度收为 0，不会白白缩进。
- 子菜单（颜色标签、换分组）自己套同一层外观，不会弹出一个系统白框。
- `--smoke-test` 会把菜单真打开，断言外壳确实是圆角的（隐式样式没被认领会静默退回系统白框，既不报错也不影响功能），并截图存证 `smoke-menu-dock.png` / `smoke-menu-launcher.png` / `smoke-menu-folder.png`。

### 把文件拖出去（微信 / 浏览器上传区 / 资源管理器）

面板里三个地方都能直接按住拖到外部程序：右侧**目录预览**的条目、**桌面分类**的文件卡片、**受管文件夹**卡片（选中多张时一次带走多个）。

- 外部程序只认 `CF_HDROP`，也就是 `DataFormats.FileDrop`；DeskMate 自己的 `CardIdFormat` / `AppPathFormat` 只有本程序看得懂 —— 只带自定义格式的话，拖出去对方一律显示「不可放置」。
- 文件夹卡片**同时带两种格式**：内部拖到另一张卡片上还是排序，拖到外部就是给路径。因此 `DragOver` / `Drop` 必须**先认内部格式**再认 FileDrop，顺序反了会把「拖到卡片上排序」误判成「再添加一次同一个文件夹」。
- 效果只给 `Copy`：拖出去是把文件交给对方处理，DeskMate 自己不移动、不删除任何东西（最高约束）。
- 路径已经不存在（列表比现场慢半拍）时不带出去，避免给对方一个死链。
- **两条系统层面的限制**，不是代码能绕的：① 对方以管理员权限（更高完整性级别）运行时，Windows 的 UIPI 会拦掉跨完整性级别的拖放；② 拖文件夹给微信会被它自己拒收（它不接受文件夹），这是对方的规则。

### 扫描桌面文件夹（不再是死路）

首次启动的欢迎窗里如果点了「以后再说」，以前就只能一个个手动添加 —— 那个询问是一次性的，写完 `DesktopScanPrompted` 就再也不弹。现在面板工具栏上一直有 **`扫描桌面文件夹`**：只把桌面上还没管理的文件夹补进来，结果照样聚成一条提示（「已加入管理：甲、乙、丙」）。

### 失效引用：能自己修

磁盘上的目录搬家、改名、软件卸载之后：

- **文件夹卡片**：红边框 +「路径不存在」（原有），右键多一项 **`重新定位到新位置`** → 弹目录框 → 只改配置里的 `RealPath`。显示名如果还是自动取的那个就跟着换，用户自己起的名字保留。新路径不存在或已经有另一条引用指着它，都会拒绝并且**保持原样不动**。
- **Dock 图标**：以前根本没有「失效」这个状态 —— 一个看着完全正常的图标，每次点都弹一个「找不到文件」。现在目标不存在时右上角出现一个红点，悬停写明「目标已不存在，右键可重新选择目标」，点它**不再抛异常**，只给一条提示；右键菜单加 **`重新选择目标`**。有效性判断跟着 2 秒一次的轮询走，而且放在后台线程（网络盘断的时候 `File.Exists` 能挂几秒，压在 UI 线程上就是整个 Dock 卡住）；软件重装回去之后红点会自己消失。

### 桌面文件归类（虚拟分类，不移动桌面上任何文件）

桌面上散落的**文件**（不是文件夹）按扩展名归成四类，直接出现在文件夹面板的顶部标签里：

**标签顺序**：`全部` → `图片` → `文档` → `压缩包` → `其他` → `未分组` → 用户自定义分组。四个分类标签带文件数（`图片 3`），**0 个也照样显示** —— 标签忽多忽少会让同一位置的点击落空。分类标签是内置视图，和「全部 / 未分组」一样不能删除。

**归类规则**（全在 `Core/Services/DesktopFileRules.cs`，可单测）：

- 一个扩展名**只属于一个分类**。映射表按 `Priority` 顺序构建且只接受第一次出现，所以不存在「.svg 算图片还是矢量图」这种要现场裁决的情况
- 这个优先级顺序**同时也是标签的排列顺序**（图片 > 文档 > 压缩包 > 其他），两条规则一份数据
- 复合扩展取最后一段：`a.tar.gz` 按 `gz` 归进压缩包
- 没扩展名、认不出来的都进「其他」

**收哪些**：用户桌面 + 公共桌面（后者也显示在桌面上，只读前者会漏一批）。只列文件，**文件夹一律不参与归类**；隐藏/系统属性、以点开头的（`.DS_Store`）、以及 `desktop.ini`、`Thumbs.db` 都被忽略。

**实时刷新**：每个桌面目录一个 `FileSystemWatcher`（不递归），Created/Deleted/Renamed/Changed 都只排一次 **350ms 去抖**的全量重扫（解压一个 zip 会连着抛十几个事件）；内部缓冲区溢出后自动重开监听并全量重扫。重扫结果变了就通知面板，回调在线程池线程上，由视图模型转回 UI 线程更新标签数量与当前分类。面板每次打开还会主动 `Refresh()` 一次，不依赖监听。

**点击语义**：双击分类里的文件 = **用系统关联程序打开这个文件本身**，与在桌面上双击完全一致；右键「在资源管理器中显示」才跳转选中。单击只是选中，不拉起外部程序。整个功能全程只读：不移动、不改名、不删除，也不写注册表 —— 分类是虚拟的，文件的真实位置始终不变。

### 启动台里不想看到的软件

两层处理：

- **内置规则**（`Core/Services/AppFilterRules.cs`）：自动滤掉控制面板小程序（`.cpl`）、MMC 管理单元（`.msc`）、纯 DLL、以及 Office 语言首选项、组件服务、计划任务、资源/性能监视器、磁盘碎片整理、各类 `helper`/`updater`/`wizard` 等系统后台组件。规则刻意保守 —— 误杀用户要用的应用比多显示几个系统工具严重得多，所以像「注册表编辑器」「MySQL Server」「Epic Games Launcher」这类名字里带系统词的正常应用都被保留，并有单元测试守着。
- **你自己隐藏**：启动台里右键任意磁贴 → **不在启动台显示**。之后顶部会出现「已隐藏 (N)」页，进去右键 → **恢复显示** 即可撤销。隐藏只写 `config.json` 的 `hiddenApps`，不卸载、不动快捷方式；被隐藏的项在 `Alt+Space` 搜索结果里也不会再出现。

### 启动台自己的应用来源

除了开始菜单与注册表 App Paths，启动台还会同步一个**快捷方式文件夹**（设置 → 通用 → 启动台快捷方式文件夹，只能设一个，默认 `%APPDATA%\DeskMate\Launchpad`）：

- 往这个文件夹放 `.lnk` 或 `.exe`，下次打开启动台自动出现（子目录也会递归扫）
- 启动台点「＋ 添加应用」选中程序后，DeskMate 会在该文件夹里**新建一个指向它的快捷方式**，并连参数与自定义图标一起转写过去 —— 不复制程序本体，也不改动你原来的文件
- 添加成功后会自动切回「全部」页并清空搜索框：停在「常用」页（新应用使用次数为 0 排不进来）或框里还留着刚才找应用的关键词，都会让新磁贴「看不见」，像是没加上
- 显式添加 = 用户此刻就是要它，所以**同一目标之前被隐藏过的会自动解除隐藏**。隐藏与去重都以「规范目标路径」为准（展开环境变量 + 还原 8.3 短路径），老配置里的短路径在载入时一次性换算，避免两种写法对不上
- 手动移除（右键隐藏）过的应用，自动同步**不会**再把它加回来
- 默认目录特意放在 DeskMate 自己的数据目录内：这样「添加应用」这个动作永远不需要往你的其它文件夹里写东西

### 启动台尺寸与滚动

面板占主屏 **70%** 并居中（`LauncherWindow.PanelRatio`），不铺满全屏；点面板外任意处（窗口失焦）或 Esc 关闭。想调比例改这一个常量即可。

超过一屏的部分**用滚轮滚**（磁贴上一滚就走，不用先把指针挪到右边的滚动条上）。这里有个 WPF 的坑：`ItemsControl` 的默认模板里**没有** `ScrollViewer`（和 `ListBox` 不一样），光在它身上挂 `ScrollViewer.CanContentScroll` 之类的附加属性完全不生效，多出来的行只是被面板裁掉 —— 表现就是「已隐藏」页有 60 多个条目，可下面那几行永远点不到，而这一页正是恢复误隐藏的唯一入口。现在自己给它的模板套了一层 `ScrollViewer`（`CanContentScroll=True` + `VirtualizingStackPanel`，按行滚，仍然只 realize 可见行）。`--smoke-test` 里带真滚轮事件校验：「全部」和「已隐藏」两页各自滚一次，滚不动就非零退出。

### 启动台毛玻璃

面板背景是**真的模糊**：打开前先把面板将要盖住的那块屏幕抓下来（`Interop/ScreenCapture.cs`，纯 GDI + `GetDIBits`，不引 System.Drawing），用 `BlurEffect`（高斯，半径 22）糊一遍当底图，上面再压一层跟着 Dock 透明度滑条的主题色调。

- 为什么不用 DWM 的 `SYSTEMBACKDROP`：那是给非分层窗口用的，而启动台必须 `AllowsTransparency=True` 才能做圆角 + 阴影 + 透出桌面，两者不兼容。
- 只在 `BlurEnabled` 打开时抓图，并且**每次呼出都重抓一次**。以前按「位置尺寸没变就复用」缓存过，结果是：开着启动台时背后是某个应用，关掉那个应用回到桌面再打开启动台，玻璃里还留着它 —— 背景不跟着现场更新。抓图 + 模糊按 **1/2 分辨率**做（`FrostDownscale`，模糊本来就没有高频细节，铺回面板看不出差别），本机实测每次约 38 ms（首次约 88 ms），日志里有 `启动台毛玻璃：重抓底图 … 用时 … ms`。
- **抓回来的像素必须按 `Bgr32` 解释**：GDI 填的第四个字节全是 0，而 WPF 把 `Bgra32` 当预乘 alpha 读，整张底图会被当成「完全透明」—— 毛玻璃抓到了却一点都看不见，面板就只剩一层色调（实测就是「屏幕中间一块白板」）。
- 深色/浅色不用单独处理：色调来自主题的 `DockBackgroundBrush`，浅色是半透明白、深色是半透明深蓝，模糊底图两种主题都成立。色调的透明度**完全跟着 Dock 的滑条**（同一个取值区间 0.2~1.0），启动台自己不再额外加下限。
- 降级：抓图失败（锁屏、安全桌面）就把底图置空，退回半透明纯色，不会白屏也不会报错。设置里关掉「毛玻璃」即彻底不抓、不糊。

Dock 本身仍然是圆角 + 柔光的近似（它只有薄薄一条，模糊收益小、代价是每次位置变化都要重抓）。

### 启动台首开不空窗：后台预热

启动台首开原本要「扫 99 个应用 → 逐个取图标」，用户按下快捷键的那一刻才开始做，就必然先看到一排空格子再逐个填上（这正是「有些图标没显示出来」的观感来源）。现在启动完成后就把 `LauncherViewModel.LoadAsync()` 排到后台（`AppShell.WarmLauncherAsync`）：扫描与取图都在 STA 线程上排队，不占 UI 线程、不拖 Dock 启动；等用户呼出启动台时磁贴和图标都是现成的。

### 开合过渡动画

启动台与文件夹管理共用 `Views/WindowTransition.cs`：**200ms 淡入**；启动台叠 **16px 上浮/下沉**，文件夹管理叠内容层 **0.96→1 的中心缩放**。都是实测换来的细节：

- **文件夹管理的关闭没有任何动画，直接 `Hide()`**：淡出淡的是内容层，而内容层自己不带背景，露出来的是窗口那块实心底色（`WindowBackgroundBrush`），屏幕上会先出现一个「同样大小、里面空空的框」再消失，加上内容同时缩到 96%，看着就像后面还有一张同样大的窗口（用户就是这么报的）。关闭那一刻用户要的是它马上不见，不是它优雅地淡走 —— 所以 `WindowTransition` 只留开启动画（`PlayContentIn`），`OnClosing` 拦下 X 之后只做一件事：`Hide()`。回归锁在 `VerifyOpenCloseAsync`：`Close()` 之后**不留一拍**就要 `IsVisible == false`。
- 启动台的关闭仍然淡出（它是分层窗口，整窗透明度可以直接动），收尾仍要 `WhenSettled`：淡出还没结束就重新呼出时，新动画会把旧时钟换掉，被换掉的时钟不再触发 Completed —— 只等 Completed 会让 `Hide()` 永远不执行。所以那里保留三层兜底：Completed + 超时定时器且只执行一次；窗口有**代际号**，过期的收尾不会把刚呼出的界面关掉；
- 淡入前先把 `Opacity` 压到 0，否则 `Show()` 的第一帧按不透明画出来、接着才从 0 淡入，就是「闪一下」；
- 启动台**不做缩放**：面板里全是要马上点中的磁贴，缩放期间位置一直在动，点下去会偏；位移只有 16px，仍落在同一个磁贴里；
- 普通窗口（文件夹管理）**不能动整窗透明度**：WPF 会把它临时转成分层窗口来合成，中间帧客户区没内容可合成，屏幕上是一个黑框 —— 这正是当初改成「只淡内容层」的原因，而它带来的副作用就是上面那条空壳框；
- 自检里**不要「等一拍再断言窗口可见」**：搜索窗与启动台都有「失焦自动关闭」的需求，而跑自检时人坐在屏幕前、鼠标就在 Dock 上蹭一下就把前台抢走了 —— 断言必须在调用之后立刻做（`Show()` 是同步的）；
- 浅色主题的色调统一压 12% 亮度（`ApplyTransparency` 里的 `Shade`）：背景是个白页面时，模糊白底 + 白色调 = 一整块纯白，读不出玻璃感。

### Dock 尺寸

设置 → 外观 → 图标大小是 **24~80 无级滑条**（不再按档跳），透明度滑条同样无级。改动经防抖后写回配置，Dock 收到 `ConfigChanged` 只重取对应尺寸的图标缓存。

### 图标为什么按「档位」取而不是按显示尺寸取

图标资源只有 16/32/48/64/96/128/256 这几档。照显示尺寸原样去要（比如滑条停在 30），Shell 只能给一张 32 的原图，鼠标一悬停放大到 1.35 倍就变成 43px —— 拉伸出来的就是「Dock 图标变糊了」。现在分两步换算：

- `DockViewModel.IconRequestSize()`：先算上悬停放大倍率（`HoverMagnification = 1.35`）
- `IconService.ExtractionSizeFor()`：再乘系统 DPI（`Interop/DpiInterop.SystemScale`），向上取到最近的一档，缓存键也按这一档建，所以 30 与 41 共用同一张图

拿到大图后由 WPF 做 **大→小**的高质量降采样（`RenderOptions.BitmapScalingMode="HighQuality"`），降采样比拉伸清晰。图标全部取完后，日志里会留一行「N 个磁贴里 M 个没取到 → 前 6 个路径」，用来区分「这张图压根取不到」和「还没轮到它」。

- Dock 的取图下限是 **96**（`DockViewModel.IconRequestSize`）：显示只有 30px 上下，取大一档再降采样，比贴着显示尺寸取更耐悬停放大与高 DPI。
- 窗口位置一律**取整**（`DockWindow.Reposition`、`ShowLauncher`、`ShowManager`）：半个像素的偏移会让整窗内容画在像素缝上，连纯矢量的图标都会发虚 —— 「Dock 图标模糊」有一半就是这个原因（贴边居中算出来的 Left 经常是 x.5）。

### 让 Dock 贴住屏幕边缘（可选，默认关闭）

设置 → 外观 → **让 Dock 贴住屏幕边缘**：勾上后 Dock 取消常规的 8px 缝隙，直接贴到它所在那条边的屏幕边缘（底部/左侧/右侧都适用）。

**DeskMate 不动系统任务栏。** 早先版本这个开关会顺手把任务栏设成自动隐藏（`SHAppBarMessage` + `ABM_SETSTATE`，本机实测可用），但那是「替用户改系统设置」，即使退出时会还原也不该由一个桌面工具去动 —— 已经整条删掉。想让 Dock 完全顶替任务栏，请自己在 Windows 设置 → 个性化 → 任务栏 里打开「自动隐藏任务栏」，DeskMate 只负责贴边。

贴边贴的是**屏幕物理边缘**。底部停靠时 Dock 会盖在任务栏那一条上（Dock 是置顶窗口，所以压得住）：任务栏图标默认靠左，Dock 水平居中正好落在中间那段空白，不挡图标、不挡右下角的时钟。

- **压住任务栏就要盯 Z 序**：explorer 会不停把 `Shell_TrayWnd` 重新抬回置顶组最上面，而 Dock 落在任务栏那 48px 里的图标一旦排在它下面，就**既收不到点击也收不到悬停**（表现是「刚启动几秒能用，之后整个 Dock 像死了」）。所以 `DockWindow.KeepAboveTaskbar` 在重叠时开一个 100ms 轮询：直接问 Z 序（`WindowInterop.IsAbove`），任务栏排在 Dock 上面就把 Dock 重新 `SetWindowPos(HWND_TOPMOST)` 抬一次。不重叠时这个定时器完全不跑，也不去跟普通窗口抢 Z 序。
- 想彻底避开任务栏：把这个开关关掉，Dock 就退回工作区底边上方 8px，完全不涉及 Z 序问题。
- 想让 Dock 完全顶替任务栏：自己在 Windows 设置 → 个性化 → 任务栏 里打开「自动隐藏任务栏」，任务栏一隐藏工作区就扩到整屏，Dock 自然贴到最底下。
- **开了「贴桌面层」时不压任务栏**：那个模式下 Dock 排在桌面图标那一层、在任务栏后面，压到物理底边等于彻底看不见，所以自动改用工作区底边。

### 遮住任务栏左边（可选，默认关闭）

设置 → 外观 → **遮住任务栏左边** + **遮罩宽度**：DeskMate 另外开一条窗口（`Views/TaskbarCoverWindow`）压在任务栏左侧的图标区上面 —— 开始按钮、搜索、任务视图、应用按钮那一段。Dock 本身位置不变。

- **是「盖住」不是「关掉」**：不写任何系统设置，任务栏进程照跑，右侧的托盘、时钟、输入法指示器都是系统原样、照常可点。开始按钮被挡住，但 Win 键照常能打开开始菜单。
- **遮罩必须是实心的**：第一版直接沿用 Dock 的透明度（用户设的 0.2），结果等于蒙了一层薄纱，图标照样看得清清楚楚 —— 盖住和半透明是两回事。填充见下一条，它是不透明的壁纸原图。
- **填充是壁纸原图，不是色块也不模糊**：`ScreenCapture.GrabBandFromWindow` 用 `PrintWindow(窗口, PW_RENDERFULLCONTENT)` 抓**桌面窗口自己渲染的内容**（壁纸），再裁出任务栏那一条。因为它问的是桌面窗口而不是屏幕，所以开多少应用、窗口怎么挡都不影响。裁出来的是原始 BGRA 像素，**先和上一帧逐字节比，真变了才建成位图**（每几百毫秒 alloc 一张 BitmapSource 没道理）。全部候选都取不到内容才退回主题底色。
- **壁纸窗口不能写死 `Progman`**：装了动态壁纸（Wallpaper Engine 等）之后，屏幕上那幅是另一个 `WorkerW` 画的，`Progman` 里还留着上一张静态壁纸 —— 照它裁就会盖上去一片和周围完全对不上的颜色。所以每次现问：`WindowInterop.WallpaperHosts()` 按 Z 序列出「可见 + 铺满整屏 + 类名 Progman/WorkerW + 不挂 SHELLDLL_DefView（那层画图标、背景透明）」的候选，`Progman` 排最后兜底，逐个试到能取出内容为止（取回来整条纯黑 = 什么都没画进去，换下一个）。
- **动态壁纸跟得上了，靠的是帧差自适应**（`Core/Services/BackdropFramePacer` + `App/Services/BackdropPump`）：以前写死 30 秒一次，在那条带子一直在动的壁纸上就是一张定格。现在 `BackdropPump` 用自己一条后台线程循环「抓一帧 → 比像素 → 变了才送回 UI 线程刷」，节奏按结果调：发现变化就减半、最低 **300 ms**，连续两帧一模一样就翻倍退让、最高 **30 秒**（静态壁纸于是和不花钱一样，换壁纸、解锁屏幕这些「变了」的事件照样会被下一帧抓到）。为什么不是固定高频：一次整屏 `PrintWindow` 本机实测 **15~26 ms**，300 ms 已经是「肉眼看得出在跟」和「后台线程十分之一的时间」之间的折中。**为什么非要一条自己的线程**：这 15~26 ms 放到 UI 线程上，等于每秒把界面按住三次，Dock 的动画和点击判定先抖起来。
- **取不到内容时不会把壁纸换成色块**：只有「从来没取到过一帧」才退回底色；已经画着一帧就留着旧帧。全屏切换、动态壁纸重启会连着几轮取不到，为此刷一块纯色比慢一帧难看得多。
- **给 `PrintWindow` 准备的画布必须是 32 位 DIB 段**（`CreateDIBSection` + `BI_BITFIELDS` 掩码），不能用 `CreateCompatibleBitmap(screenDC, …)`：GPU 合成的那一层往 DDB 里画会「返回成功但一个像素都不写」，屏幕上就是一块纯黑。
- **Z 序按帧率盯**：遮罩是「看」的，任务栏抢回去的那一瞬间用户就会看到图标闪一下，所以轮询是 16ms（Dock 那条只关心点击，100ms 足够）。判据是直接问 Z 序（`WindowInterop.IsAbove`，沿 `GW_HWNDPREV` 从任务栏往上走）。**不能**用「我自己那个像素归不归任务栏」来判断：任务栏是带逐像素透明的分层窗口，探测点落在透明段时 `WindowFromPoint` 会一路穿透、返回我们自己的窗口，于是明明被压着却判成没被压着，屏幕上就是图标一闪一闪。Dock 贴边时也用同一条判据（100ms）。
- **不会越过 Dock**：宽度会自动钳到 Dock 左沿前 8px；如果 Dock 本来就贴在左边、没有可盖的空间，遮罩直接不显示（日志里会写明原因）。
- 只在任务栏位于**底部**时生效：任务栏在左侧/顶部或已被用户自己隐藏时，那条带子不存在，遮罩自己收起来。

### 已运行的应用：切回去，而不是再开一个

点击 Dock 图标的语义与任务栏一致：

- 该应用**没有**窗口 → 启动一个新实例
- 有窗口且其中某个**正在前台** → 把它最小化
- 有窗口但都不在前台 → 切到最上面那个窗口
- 进程活着但窗口被应用自己 `hide()` 了（微信、QQ 这类「关窗口只是缩回托盘」）→ 也只能重新拉起，见下面的说明

实现走 `IWindowService`：按 exe 名找进程 → `EnumWindows` 过滤出「算一个任务」的窗口（排除工具窗、子窗、带 owner 的弹层、被 DWM 遮罩的挂起窗口，判定规则照抄任务栏）→ 激活。
若撞上 Windows 的**前台锁定**（非前台进程不能随便抢焦点），会补发一次 Alt 键让系统认为是用户输入，仍失败再退回 `SwitchToThisWindow`。

**为什么缩回托盘的应用不能「唤回来」**：微信 4 关窗口是把主面板在 Qt 层 `hide()` 掉（原生窗口没有 `WS_VISIBLE`，进程还留在托盘）。这时从外面 `ShowWindow` 只会得到一个**没有内容的白框** —— 它的 widget 已经是隐藏状态、不会重绘，实测踩过，比再开一个实例更糟。所以窗口判定**只认可见窗口**，这种状态一律交给启动流程；日志里会留一行 `Weixin 有 5 个进程，但没有可见窗口（大概是缩回托盘了）`，一眼能分清「没在运行」和「藏在托盘」。
要真正像点托盘图标那样把它叫回来，得走通知栏的 UIA Invoke（还要处理图标在溢出区、各家实现不一致），v1.0 没做。

### 拖动排序（带视觉反馈）

固定项按住左键拖到目标位置松手即可换位（超过系统拖动阈值才进入拖拽，所以普通点击不会被误判成拖动）。三件让这件事"看得见、拖得准"的细节：

- **被拿起的那一枚压成半透明**（0.35），松手前一直保持 —— 没有这个信号，拖动过程在屏幕上什么都读不出来。
- **一条插入位置指示线**跟着光标走：横着贴边时是竖线、竖着贴边时是横线，位置用 `RenderTransform` 改，元素本身不参与布局（改 `Margin` 会引起重排，正是这条 Dock 一直在避免的）。
- **拖拽期间暂停运行区的 2 秒轮询**，松手后立刻补一次快照。`DoDragDrop` 自己会泵消息，不停的话轮询会在你手底下把容器 Move/Insert 一遍，插入点当场就算错了（表现就是"图标自己跳、拖不准"）。同时拖拽期间屏蔽悬停让位动画与窗口预览。
- 拖拽只作用于**固定区**：运行区的临时项本来就不在配置里，`ReorderAsync` 会忽略它们。
- 自检里的 `VerifyDockDragFeedbackAsync`（`ShowDragFeedbackForSelfCheck` + 截图 `logs/smoke-dock-drag.png`）会把这套视觉状态摆出来验一次位置与可见性 —— 这台机器上合成输入起不了 OLE 拖拽循环（`SetCursorPos` + `mouse_event` 试过，WPF 根本没进 `DoDragDrop`），所以只能这样验。

### 悬停预览

鼠标在已运行的图标上停 **160ms**，图标上方会浮出该应用所有窗口的**实时缩略图**（最多 6 个，带标题），点某一张就切到那个窗口；每张卡片标题行右侧有一个 **×，只关掉那一个窗口**（同样走 `WM_CLOSE`）；离开图标与预览后自动收起。

× 画在标题行而不是缩略图上，是因为缩略图由 DWM 合成、画在它里面的 WPF 内容会被盖住；这也是 Windows 自己的任务栏预览把 × 放在标题一侧的原因。自检 `VerifyPreviewCloseAsync` 会确认每张卡片的 × 热区非空、且不与「切窗口」热区重叠（重叠的话点 × 会先切窗口，看着就是 × 失灵）。
应用缩回托盘（窗口被 hide）时没有任何窗口可预览，浮层就不出现 —— 这时点图标等于重新打开应用。

这段等待以前是 450ms，而且计时结束才开始 `EnumWindows` 找窗口，两段串起来就是「明显卡了一下才弹」。现在三处一起改：

- 悬停一开始就把窗口枚举排到后台线程（`SchedulePreview` 里的 `_pendingPreviewWindows`），160ms 到点时结果通常已经在了
- 延迟本身从 450ms 降到 160ms：再短就会在鼠标扫过时弹成干扰
- 同一批窗口再次悬停**不重新注册 DWM 缩略图**（`WindowPreviewWindow.IsSameSet`），只更新标题与位置；重新注册是几十毫秒量级的白等

**多窗口时"点第二张却选中第一张"是两个几何 bug**（开两个 Word 时最容易撞到）：

- DWM 要挂上句柄之后才报得出源窗口的真实比例，所以卡片的实际尺寸只能在 `AttachThumbnails` 里定；可以前**只改了每张的宽高、没有重算它们的 X 和 `Canvas.Left`** —— 两张卡片于是会互相压住十几像素，而点击判定是按 `Bounds` 顺序遍历取第一个命中的，压住的那片区域永远归前面那张。现在 `AttachThumbnails` 按修正后的宽度**整排重排**（X、`Canvas.Left`、标签位置、`Bounds` 一起重算）。
- 整排重排后总宽度变了，但 `Left/Top` 是**在尺寸定下来之前**算的 —— 整排会相对图标偏出去，右边那张可能被屏幕边缘裁掉。现在重排完再 `Position()` 居中一次，最后才把 DWM 目标矩形按最终 `Bounds` 写回去。
- 另外**收起预览改成反复检查**（每 260ms 问一次），不再用一次性定时器：从图标滑到预览上，中间要穿过 Dock 的透明边距和两者之间那 6px 间隙，那一段两边都不算悬停，一次性定时器恰好会在你走到一半时把预览收掉。判据也从「只在 `Chrome` 上」放宽到「在整个 Dock 窗口上」。
- 鼠标从预览滑回图标时不再立刻自关（以前 `MouseLeave` 直接 `DismissRequested`），收不收统一交给上面那个看门狗。

判据用的是刚枚举出来的窗口列表，所以「窗口已经关了」这种情况一定会走重建分支，不会把旧画面留在预览里。超过 6 张时末尾给一个 `+N`，跟着卡片一起重排。

缩略图用 `DwmRegisterThumbnail` + `DwmUpdateThumbnailProperties`，由 DWM 在合成阶段直接搬运源窗口画面 —— 所以它会实时动，也不占我们的 CPU。承载预览的浮层刻意**不用** `AllowsTransparency`（分层窗口与 DWM 缩略图合不来），圆角与描边走 Windows 11 的 `DWMWA_WINDOW_CORNER_PREFERENCE` / `DWMWA_BORDER_COLOR`。

## 8. 操作反馈：非模态提示浮层

以前每个窗口都把自己的 `UserNotice` 接到 `MessageBox.Show` 上 —— 一个常驻桌面工具每做一步都要用户点一次确定，而 Dock 是 `ShowActivated=False` 的置顶无焦点窗口，模态框落在别的程序后面，观感就是「点了一下没反应」。现在统一成 **`ToastService` + `Views/ToastWindow`**：

- 不抢焦点、自动消失（普通 2.6 秒、错误 3.6 秒）、最多叠 3 条、点一下即关；贴在 **Dock 正上方并水平对齐 Dock 中心**（动作是在哪儿做的，提示就出现在手边），Dock 不可见时退回工作区底部居中。
- 各视图模型只负责说话：`UserNotice` 事件带 `NoticeEventArgs{Message, Kind, ActionLabel, Action}`，由 `AppShell` 统一转给浮层。**加新窗口不用记得再挂处理器**，也不会再各写一个模态框。
- 只有需要用户拿主意的地方保留模态框：重置为默认、导入配置、删除分组 / 批量移除引用、首次启动的欢迎窗、快捷键注册失败、以及改名与换图标的输入框。
- **左色条跟着分量走**：信息=主题色、成功=绿、注意=琥珀（新增的 `WarningBrush`，两套主题都有）、失败=红。
- **批量操作聚合成一条**：拖 10 个文件夹进面板 = 一条「已加入管理：…」，有失败的再补「另有 N 项没加上」并转成琥珀色。同一个词短时间内重复出现只续期不叠条。
- **提示上可以带动作**：删除分组后的「撤销」、就是浮层右侧的一个小按钮。
- 自检会把浮层出现的那一帧截成 `logs/smoke-toast.png` 存证（见第 3 节）。

## 9. 快捷键与入口

搜索、启动台、文件夹面板**各一个**全局快捷键（`AppConfig.Hotkey` / `LauncherHotkey` / `FolderHotkey`），设置 → 通用 里三行输入框分别捕获，每行旁边有「不绑定」。

- 搜索仍是 `Alt+Space`；**启动台与面板默认不绑定** —— 一个桌面工具不该未经同意就抢走系统按键。
- 三个入口都能从**托盘菜单**走到（新增 `打开搜索`、`重新扫描应用`、`使用说明`），Dock 上也有启动台与面板两个按钮。以前全局搜索只有 `Alt+Space` 一个入口，被中文输入法占走之后整个功能在 UI 里**点不到**，这是断头路。
- 注册时三组一起比：**两个入口用了同一个组合**会直接说「与另一个入口撞了」；搜索那组失败弹模态框并指路（换键之前托盘也能打开），另外两组失败走非模态提示。
- 快捷键的**动作**在自检里被真实调用并断言窗口可见（合成按键在这台机器上送不到全局热键，所以验动作而不是验按键）。
- 启动台与面板的切换语义：没开 → 呼出；开着但在后面 → 提到前面；开着且在前台 → 收起。

## 10. 搜索能搜到什么

`SearchService` 现在合并五个来源，全部支持拼音首字母（与启动台同一套 `PinyinMatcher`）：

| 来源 | 类型标签 | 回车 |
| --- | --- | --- |
| 已安装应用（开始菜单 + App Paths + 启动台文件夹） | 应用 | 启动 |
| 受管文件夹本体 | 文件夹 | 资源管理器打开 |
| Dock 上的固定项 | 应用 | 启动 |
| **桌面上的文件** | 文件 | 用系统关联程序打开 |
| **受管文件夹的一级内容**（含子目录） | 文件 / 文件夹 | 打开文件 / 打开目录 |

- 受管目录的内容只索引**一级**、每个目录限 300 条、结果缓存 30 秒；`.git`、`.vscode`、`desktop.ini` 这类点号开头与 shell 自留文件不进索引（与桌面分类同一条规则）。整段匹配跑在线程池上 —— 搜索是边打字边触发的，不能占 UI 线程。
- **文件类结果最多占 8 个名额**：输一个「a」能命中成百上千个文件，不设上限应用就会被挤出结果列表，而这里最常用的动作仍然是启动应用。
- 零结果时底部出现两个按钮：**`重新扫描应用`**（刚装的软件在这里补扫一次，走的是启动台那条刷新路径，所以两边一起更新）和 **`在资源管理器中搜索`**（`search-ms:` 交给 Windows 索引 —— 全盘内容检索本来就不是这里该重造的东西）。
- `Ctrl+Enter` = 到资源管理器里选中它；结果条目右键有 **打开 / 在资源管理器中显示 / 复制路径**。

## 11. 应用列表怎么保持新鲜

装完新软件不必重启 DeskMate：

- **每次呼出启动台**都在后台重扫一次（`LauncherWindow.ShowLauncher` → `RefreshAsync(report: false)`）。采纳判据是**按 Id 比集合差异**，不是比数量 —— 一装一卸时总数不变，旧写法永远发现不了。
- 启动台工具栏有 **`刷新应用`** 按钮、支持 **F5**，托盘菜单有 **`重新扫描应用`**，搜索零结果时也有入口。手动刷新会播报「新增 N 个，移除 M 个，现在共 K 个」，后台静默对齐不播报。

## 12. 数据与配置的安全边界

- **写盘失败会退回**：`ConfigService.SaveAsync` 失败时先把内存退回磁盘上最后一次成功的状态再抛错（临时文件 + 替换保证磁盘上不会有半个 JSON），调用方随后重载列表并提示「已退回改动前的样子」。以前界面会显示一个根本没存进去的删除，重启后条目又凭空回来。
- **导入配置前自动备份**成 `config.json.bak-<时间戳>`，并且先弹确认（写清当前有多少 Dock 项 / 文件夹 / 分组会被换掉）；失败文案按「有没有开始动过」区分，不再一律说「当前配置未被改动」。导出走系统保存框，同名会先问。
- 设置 → 数据 页新增 **打开数据目录**、**打开日志文件夹**、**清空启动统计**（后者立即落盘，不然下次启动历史数据又回来了）。
- 从 Dock 切回窗口**也计入使用次数**：只统计「新启动」的话，一天切几十次的微信永远进不了「常用」页。

## 13. 首次启动

欢迎窗（`Views/WelcomeWindow`）取代了原来那个「要不要导入桌面文件夹」的是/否框：三条上手提示（往 Dock 拖什么、Alt+Space 能搜什么、桌面分类是虚拟的）+ 检测到几个桌面文件夹 + `把这些文件夹加入管理` / `以后再说`。只自动弹一次，之后随时能从托盘 **`使用说明`** 再打开；就算第一次点了「以后再说」，面板工具栏上的 **`扫描桌面文件夹`** 一直可用。

## 14. v1.0 已知限制

- **受保护内容的窗口取不到缩略图**（部分播放器/安全软件），此时预览卡片退化成只有标题的方块，但仍然可以点。
- **缩回托盘的应用（微信、QQ）点图标只能重新拉起**：它们的窗口在工具包层就被自己隐藏了，外部 `ShowWindow` 唤不回正确画面，详见第 7 节。现在这种状态**会在悬停文字里写明**（「正在运行，但窗口缩回了托盘 · 点图标会重新打开它」），不再让人以为是重复启动的 bug。要真正像点托盘图标那样把它叫回来，得走通知栏的 UIA Invoke。
- **悬停预览一次最多 6 张**：超出会在末尾显示 `+N`（以前是静默截断，浏览器开十几个窗口时看着像只有 6 个），但多出来的窗口不能从预览里直接切。
- **多显示器**：Dock、启动台、搜索、提示浮层都按主屏工作区定位（`SystemParameters.WorkArea`）。`Reposition()` 改成接收目标屏即可扩展。
- **Dock 的毛玻璃是近似效果**：`AllowsTransparency=True` 的分层窗口不接受 DWM 背景采样，所以 Dock 那条仍然是圆角 + 柔和外投影（启动台已经改成自抓屏幕 + 高斯模糊的真毛玻璃，Dock 没跟上是因为它每次位置变化都要重抓，收益不抵开销）。
- **UWP 只覆盖开始菜单里有快捷方式的那些**（需求把直接枚举 appx 包标为 v1.1）；`.appref-ms` 类型的条目会被跳过。这类条目的图标现在能正常显示，走的是下面的 Shell 兜底路径。
- **启动台没有「应用自定义分组」**：需求第五节的数据模型里没有对应结构，v1.0 只做「全部 / 常用 / 已隐藏」；文件夹分组是完整的。
- **常用页只按启动次数排序**，时间衰减留给 v1.1。
- **贴桌面层模式是实验性**：依赖未公开的 `0x052C` 消息，Windows 11 24H2 之后桌面改成 XAML 岛，挂接可能失败 —— 失败时自动退回普通置顶，不会让 Dock 消失；**成没成现在会用一条提示说出来**（这个开关的效果本来就看不见摸不着）。
- **还没有做的键盘导航**：卡片与磁贴仍然是 `Focusable=False`，`F2` / `Delete` / `Ctrl+A` 走的是窗口级按键，方向键不能在网格里移动焦点；分组 Tab 也不能拖拽排序。
- **几个小口径不一致还留着**：从面板双击打开文件夹不计入使用次数（只有从搜索打开才计），「已隐藏」列表没有一键全部恢复，`usage.json` 不删已卸载应用的残留计数，开机自启项在换了 `DeskMate.exe` 目录后只会显示成「未开启」而不会提示更新。
- **动态壁纸下任务栏遮罩那一条最多落后 300 ms**：靠帧差自适应追（见上面那节），不是原样同步 —— 一次整屏 `PrintWindow` 实测 15~26 ms，追到屏幕帧率既不划算也会吃满一条线程。壁纸不动时它会退到 30 秒一次，不占资源。
